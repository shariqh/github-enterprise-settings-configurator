# SE results interpretation agent

`.github/agents/se-results-interpreter.agent.md` gives a GitHub Solutions
Engineer a decision-ready, internal interpretation of one configurator JSON
export. It never inspects or changes a tenant, and it never edits this
repository.

## Invocation

The agent is manual-only: `user-invokable: true` and
`disable-model-invocation: true`, so it only runs on an SE's explicit request
and is never triggered by the model on its own. Its mechanical tools are
limited to `read` and `search` — there is no edit, shell, Git, GitHub CLI, or
tenant-mutation capability, so it cannot propose a patch, open an issue or
pull request, or apply anything to a customer tenant.

Invoke it from the GitHub Copilot CLI with the current JSON export attached or
pasted, for example:

```bash
copilot --agent se-results-interpreter
```

Then share the exported file and, optionally, a short redacted context
summary (rollout stage, operating model, known constraints — nothing else).

## Input contract

- **Required:** the current schema-v2 JSON desired-state export from the
  Review step (`schema.name` =
  `github-enterprise-settings-configurator.desired-state`, `schemaVersion` =
  `2`), including its `profile`, `capabilityContext`, `readiness`, `settings`,
  `caveats`, `domainProfiles`, and `excludedDecisions`. The Markdown handoff
  export, screenshots, and prose descriptions are not accepted in v1.
- Missing, malformed, wrong-schema, or non-JSON input fails closed with an
  exact request for a fresh JSON export — the agent does not guess.
- Optional context must already be redacted. The agent refuses raw
  transcripts, named individuals, customer/account identifiers, deal or
  contract data, and credentials, and asks for a redacted summary instead.

## Synthetic invocation example

The export below is **genuinely valid and current** — it is not hand-written.
It was generated by calling this repository's own `getRecommendedSettings`
and `exportObject` (`src/logic/recommendations.ts`, `src/logic/export.ts`)
against a real, capability-compatible profile (GitHub Enterprise Server,
instance accounts, SAML with the SCIM public preview, Secret Protection and
Code Security licensed, no Copilot license — GHES cannot license Copilot).
Every setting ID in it is a real, current catalog ID. No customer name,
transcript, or account data appears anywhere in it. The full file lives at
[`tooling/se-results-interpreter/fixtures/synthetic-export.json`](../tooling/se-results-interpreter/fixtures/synthetic-export.json)
and is round-tripped through this repository's own
`parseImportedPlan` (`src/logic/persistence.ts`) importer, and recomputed
byte-for-byte, by the `src/logic/seResultsInterpreterFixture.test.ts` suite
described under "Static enforcement" below — proof it is accepted by the
configurator itself, not merely schema-shaped.

Redacted context an SE might add alongside the file:

> Rollout stage: early pilot with the platform team. Operating model:
> GitHub Enterprise Server with instance accounts, SAML SSO, and the SCIM
> public preview. Known constraint: must remain self-hosted through the next
> fiscal quarter.

A trimmed excerpt (the full export also carries `catalog`, `intent`,
`planningContext`, `summary`, `implementationSteps`, and the full rationale,
sources, and choices for every decision):

```json
{

    "version": 2
  },
  "schemaVersion": 2,

    "artifactStatus": "draft",

    "isReady": false
  },

    "profileErrors": [],
    "profileWarnings": [
      {
        "code": "ghes-scim-preview",

    { "code": "default-no-exclusions", "message": "13 catalog decisions are excluded by the resolved capability model.", "decisionIds": ["code-quality-targeting", "copilot-license-topology", "..."] }

    { "domain": "Organization & repository governance", "postureLabel": "Higher", "foundationLimited": true }

  "settings": [
    { "id": "admin-redundancy", "domain": "Identity & administration", "disposition": "Recommended", "reviewStatus": "reviewed", "role": "Enterprise owner" },

  ],
  "excludedDecisions": [
    { "id": "copilot-license-topology", "domain": "Copilot governance", "applicability": { "status": "excluded", "reason": "Excluded by catalog availability: requires at least one of `copilot-business`, `copilot-enterprise`." } }
  ]
}
```

Given the full input, the agent's briefing would, among other things:

- Report the **plan-level** `readiness.status` as `draft` (1 of 16 applicable
  editable decisions is `not-reviewed`) — kept distinct from the
  **decision-level** `settings[].reviewStatus` breakdown (15 `reviewed`, 1
  `not-reviewed`).
- Describe `default-branch-ruleset` as an open **Override** to confirm with
  the customer's repository administrators — the export records it as a
  deliberate weaker choice (`advisory`), not an error.
- Report `"Organization & repository governance"` as a **foundationally
  limited domain** (`domainProfiles[].foundationLimited: true`), state
  plainly that the export does not identify which specific decision in that
  domain caused the limit, and direct the SE to review that domain's
  decisions with the customer rather than guessing.
- Describe the 13 excluded decisions (Code Quality and Copilot governance/cost
  settings) as a **capability gap for this profile** — GHES has no Copilot
  license and Code Quality is unlicensed here — not a statement about the
  customer's live tenant or a permanent "no."
- Cite the `ghes-scim-preview` entry in `capabilityContext.profileWarnings`
  as evidence to recheck before the next meeting, since GHES SCIM is a public
  preview.

## What it will not do

It will not claim observed tenant state, compliance/ATO status, approval,
automatic application, guaranteed availability or parity, pricing, a
timeline, a root cause, a legal interpretation, or a single composite score
across domains. `domainProfiles` are reported as separate, relative signals.
It will not name a specific decision as "the" cause of a foundation-limited
domain unless the export actually identifies one. Any customer-facing recap
remains a separate, human-authored artifact.

## Static enforcement

```bash
pnpm test                        # includes the fixture-genuineness suite
pnpm se-results-interpreter:test # agent/doc contract checks
```

`src/logic/seResultsInterpreterFixture.test.ts` (part of `pnpm test`) proves
the fixture is genuinely valid, not merely schema-shaped: it runs the fixture
through this repository's own `parseImportedPlan` import path, asserts its
profile has zero capability/compatibility errors, cross-checks every
referenced setting ID against the live catalog, and recomputes the export
with `getRecommendedSettings`/`exportObject` to diff it byte-for-byte against
the checked-in file.

`tooling/se-results-interpreter/test/se-results-interpreter.test.mjs`
(`pnpm se-results-interpreter:test`) checks the agent's frontmatter
(`user-invokable: true`, `disable-model-invocation: true`,
`tools: ["read", "search"]`, and the absence of any
edit/shell/GitHub/tenant-mutation tool), the required
input/privacy/interpretation/output-contract language — including the
plan-level/decision-level distinction and the exact
`capabilityContext.profileWarnings` citation — the prohibited-claims
guardrails, and that the fixture declares the required top-level fields and a
real profile shape.

The required `verify` job in `.github/workflows/ci.yml` runs both `pnpm test`
and `pnpm se-results-interpreter:test` on every pull request and push to
`main`.
